# BreakTrace generalization audit

This is the starting-state audit for Phase 2 of product development. The earlier demo benchmark is historical evidence for the bundled fixture, and the implementation work is tracked in [TASKS.md](../TASKS.md).

| Original requirement                     | Starting state                                                                                                                                  | Gap                                                                                                                                                                                            |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A · API discovery and version comparison | Playwright captures fixture requests, response types, status, timing and initiating page. The API compares baseline shapes between runs.        | Discovery only recognizes the demo API prefix. OpenAPI 3.0/3.1 JSON imports are global descriptive records. YAML, project-level assignment and configurable operations are missing.            |
| B · API failure simulation               | All requested mutation families are implemented and the demo benchmark exercises them.                                                          | Target matching and API methods are coupled to the demo. Authorized applications need independent endpoint configuration.                                                                      |
| C · Frontend impact                      | Baseline and mutant Chromium contexts collect assertions, rules, navigation, console and runtime events, screenshots and timings.               | Workflows only accept five hardcoded paths, a fixed selector convention and a demo error marker. Browser and transport containment for external content are unverified.                        |
| D · Dependency graph                     | React Flow renders observed nodes and labels inferred edges.                                                                                    | Evidence is scoped to a chosen run. The graph does not establish actual JavaScript field reads or comprehensive application coverage.                                                          |
| E · Minimum failure isolation            | Bounded subset/complement search uses clean controls and repeated matching signatures.                                                          | Benchmarked on one demo workflow. There is no globally minimal guarantee or result for external applications.                                                                                  |
| F · Silent bugs                          | Configurable range, equality and sum-product rules use DOM values or literals.                                                                  | Rule data access assumes numeric `data-value` attributes. Workflows and rules share a global demo-first configuration.                                                                         |
| G · Regression generation                | Real Playwright specs reproduced all 20 labeled demo failures.                                                                                  | Generated setup starts the bundled fixture; equivalent external setup and authorization are missing.                                                                                           |
| H · Repair and AI                        | The approved, reviewed demo patch is verified in a copied fixture. A real optional Ollama adapter exists.                                       | The current model adapter has not run against a local model. External code patching is outside the approved demo repair boundary.                                                              |
| I · Deployment assessment                | Deterministic score, JSON reports, configurable thresholds and CLI exit codes passed local checks.                                              | Endpoint coverage uses the fixture denominator. Hosted Actions and container checks have no execution evidence.                                                                                |
| Storefront                               | Listing, details, cart, discounts, availability, mock checkout and confirmation work. False-positive controls are recorded.                     | The store is synthetic by design. Benchmark evidence does not generalize to production systems.                                                                                                |
| UI                                       | All fifteen screens have local routes. The original Playwright test exercises the main demo run, evidence, regression preview, repair and gate. | Project configuration is demo-only. Several configuration forms, empty states, responsive navigation and download actions lack automated coverage.                                             |
| Data and processing                      | A JSON catalog and per-run records persist data. A bounded in-process queue serializes Chromium jobs.                                           | MongoDB is missing. Multi-operator auth, durable distributed jobs and object storage are absent. Redis/BullMQ were optional infrastructure in the original brief.                              |
| Security                                 | Loopback-only API, Host/Origin checks, no redirects, isolated contexts and sanitized shapes.                                                    | External origins need operator approval, target consent, DNS/IP enforcement, and a browser network policy.                                                                                     |
| Engineering and evaluation               | Locked npm dependencies, local tests, Docker and CI definitions, documentation, and a real 30-case benchmark.                                   | Container and hosted CI execution are unverified. Optional model and external targets require separate evidence. The dashboard uses native components with Tailwind/CSS in place of shadcn/ui. |

The bundled demo workflows and historical benchmark records are compatibility fixtures for Phase 2. Live deployment and external mutating requests are outside this workspace's execution scope.

## Dashboard control audit

The route inventory was traced through the React handlers and their API calls. Browser coverage includes the full navigation inventory, the bundled demo flow, the staging enrollment flow with a synthetic transport, and mobile keyboard navigation. Controls with a prerequisite expose that state before dispatching an action.

| View                       | Controls and prerequisites                                                                                                                                                                                                                                                     |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Landing                    | The brand and Settings documentation link open the landing view. Open workspace returns to Overview.                                                                                                                                                                           |
| Overview                   | Run demo experiment queues the three-mutation fixture. New execution and All runs open execution controls. Recent rows open the chosen run. Risk trend uses saved assessments.                                                                                                 |
| Projects                   | Select a project or add and save a demo or external draft. External operations and screenshot opt-in are saved with the project. Create challenge requires staging acknowledgment and an allowlist entry. Verification and confirmed revocation call the authorization routes. |
| API explorer               | Expand captured response shapes, select two baseline runs to compare, and import a pasted or uploaded JSON/YAML document. Registration is a separate opt-in for read-only methods.                                                                                             |
| Workflows                  | Select an existing workflow or create a starter. Select an external project for a scoped template. Save validates the JSON steps and rules.                                                                                                                                    |
| Failure scenarios          | Select or create a scenario, choose scope before adding mutations, and edit operation, operator, and operator operands. Add/remove affect the local draft. Save persists the ordered set.                                                                                      |
| Test executions            | Select a project, scoped workflow and scenario. External executions require authorization. Each listed run opens its own status and evidence.                                                                                                                                  |
| Dependency graph           | Node clicks and the node selector inspect evidence. The canvas has pan, zoom and fit controls. A selected run is required.                                                                                                                                                     |
| Failure details            | Both execution records, per-rule results and applied mutations come from the run. Root-cause, graph and experiment links retain its ID. Screenshot and visual-diff links require corresponding artifacts.                                                                      |
| Root cause analysis        | Deterministic guidance reads the run. The Ollama action requires an explicitly configured local model. The repair link is conditional on the reviewed demo patch criteria.                                                                                                     |
| Experiment history         | Trial rows, finding signatures and the isolated subset come from the selected run. A run without isolation shows its empty state.                                                                                                                                              |
| Regression tests           | Preview and .spec.ts download use the same API generator. A completed run with browser evidence is required.                                                                                                                                                                   |
| Repair verification        | An explicit checkbox enables the reviewed patch action for eligible demo runs. The panel displays the persisted rerun and source preservation checks.                                                                                                                          |
| Deployment risk            | The score and factors use the completed run. Export JSON downloads its report from the API.                                                                                                                                                                                    |
| Settings and documentation | Thresholds persist after validation. Product overview opens the landing page. The theme toggle and mobile navigation remain available while browsing settings.                                                                                                                 |

The hosted workflow and a real Ollama model require separate verification. The locally exercised site uses the bundled demo or the synthetic staging transport.
